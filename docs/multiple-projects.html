Follow the repository, then the run

A Project groups local repository paths and can provide shared agent or skill defaults. A pipeline is the reusable sequence of work. A run selects its primary repository, source branch, pipeline, and task.

1

Group and find the work

PDO's Runs page can group runs by their primary checkout. Add a named Project when several paths belong to one product or team.

2

Choose where and how a run starts

Every run needs a target repository and source branch. Pipelines live in the shared PDO instance, so select one that fits that repository.

Separate products? Launch a separate run on each repository. You can keep one PDO daemon and, when appropriate, reuse the same pipeline.

3

Add a second repository only when the task needs it

For a task crossing repositories, the New Run form can add a secondary checkout. After launch, the Repositories tab identifies what the run actually used.

Before publishing: inspect each node's inputs and outputs, the run's Repositories and Diff tabs, and the Git remote for every checkout you intend to change.
